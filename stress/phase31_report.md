# Phase 31 — Educational Quadratic Step Redesign Report

Branch: `feature/expression-solver`
Date: 2026-08-29

## Objective

Redesign the **quadratic equation** solution steps on the canonical `/solve`
path from generic one-line descriptions into genuinely educational steps that
teach formula → substitution → result at every stage, without changing any
mathematical behavior.

## Existing Behavior (before)

Six steps, mostly generic (`x² - x - 12 = 0`):

```
Step 1 [normalize_quadratic]    latex: x^{2} - x - 12 = 0
Step 2 [extract_coefficients]   latex: x^{2} - x - 12 = 0        (no a, b, c shown)
Step 3 [compute_discriminant]   latex: 49                        (result only)
Step 4 [classify_roots]         latex: (empty)                   (only the applicable case stated)
Step 5 [quadratic_formula]      latex: (empty)                   (no formula, no substitution)
Step 6 [simplify_roots]         latex: (empty)                   (separate step, no content)
```

## New Behavior (after)

Five educational steps:

```
Step 1 [normalize_quadratic]    x^{2} - x - 12 = 0
Step 2 [extract_coefficients]   a = 1,\quad b = -1,\quad c = -12
Step 3 [compute_discriminant]   aligned: D = b² - 4ac
                                         D = (-1)² - 4(1)(-12)
                                         D = 49
Step 4 [classify_roots]         gathered: D > 0 ⇒ two distinct real roots
                                          D = 0 ⇒ one repeated real root
                                          D < 0 ⇒ two complex roots
                                          D = 49 > 0 ⇒ exactly two distinct real roots
                                description additionally states all three cases
                                in prose and connects the current D to its case
Step 5 [quadratic_formula]      aligned: x = (-b ± √D)/(2a)
                                         x = (-(-1) ± √49)/(2(1))
                                         x = (1 ± 7)/2
                                         x₁ = 4, x₂ = -3
```

Final result area unchanged: contains only `x_1 = 4, x_2 = -3`.

## Architectural Reasoning

- **Rules own their explanations.** Each rule's enriched step is generated by
  the rule that performed the operation, from the values it already computed —
  no second calculation layer, no frontend-hardcoded math, no per-equation
  canned text.
- **Pipeline preserved.** All six rules still run in the same order; the
  simplify rule still executes and feeds `simplified_roots`. Only the
  *presentation* merged: its roots become the closing line of the formula
  step (`_merge_formula_step` in the solver — pure orchestration, no math).
- **Step model untouched.** Everything fits the existing
  `title/description/latex/metadata` contract; new metadata keys are additive.
- **Final answer untouched.** `_render_answer` is byte-identical; verified by
  byte-comparison across all Phase 31 cases and by the full P28/P29 suites.
- Legacy `/predict` path automatically inherits the richer steps (both
  reasoners are relays).

## Step Structure (all cases)

1. **Standard form** (`normalize_quadratic`)
2. **Coefficients** (`extract_coefficients`) — explicit `a`, `b`, `c`
3. **Discriminant** (`compute_discriminant`) — formula, substitution, result
4. **Root classification** (`classify_roots`) — all three cases + current case
5. **Quadratic formula** (`quadratic_formula`) — formula, substitution,
   evaluation, simplified roots (simplification merged here)

## Edge Cases

- **Repeated root:** formula step shows `x = (6 ± 0)/2` then `x = 3`;
  classification connection reads `D = 0 ⇒ exactly one repeated real root`.
- **Complex roots:** substitution shows `√(-4)`; evaluation `x = (0 ± 2i)/2`;
  roots `x₁ = i, x₂ = - i`.
- **Negative leading coefficient:** normalize flips sign first, so the
  coefficient step shows the canonical `a = 1, b = -5, c = 6`.
- **Fractional coefficients:** all substitutions render exact Rationals
  (`\frac{1}{2}`), no decimal drift.
- **JSON safety:** all new step content is plain strings; metadata roundtrip
  verified over HTTP.

## Known Limitations

- The discriminant is displayed as `D` (matching the product spec); `Δ` was
  not used.
- The classification connection line reuses the `root_count` phrasing
  ("exactly two distinct real roots"), which is slightly more verbose than
  the case labels above it — intentional, deterministic, and content-checked.
- Linear and derivative steps remain generic (explicitly out of scope; later
  phases).
- `b = 0` renders as `-(0)` in substitutions — literal substitution is
  deliberate for teaching value placement.

## Final Verdict

**Phase 31: SUCCESS.** Quadratic final answers are byte-identical to the

now 5 educational steps teaching formula → substitution → result at every
stage; no architectural duplication; no unrelated capability modified.
